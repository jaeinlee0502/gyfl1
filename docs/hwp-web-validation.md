# HWP 직접 읽기·드래그 앤 드롭 검증

2026-11-02, 공개 웹 버전 대상. 실제 시험/학생 자료 없이 생성한 가상 HWP만 사용했습니다.

## 구현

- HWP 5.0/5.1의 CFB/FileHeader/DocInfo/BodyText를 브라우저 worker에서 직접 읽음. 압축/비압축 본문과 기본 문항 표를 지원
- 파서 실행 전 버전/보호 플래그/섹션 연속성/레코드 경계/압축 해제 예산 검사. 암호화·DRM·ViewText·HWP 97/3.x는 안내 후 거절. 미리보기 텍스트로 본문을 대신하지 않음
- HWP 추출은 모든 필드에 원문 확인을 요청하고 실제 섹션·표·행 또는 문단을 근거로 제공. 전체 문항 내용/자동번호/수식/그림/복잡한 배치를 보증하지 않음
- 파일 선택과 두 영역의 드롭에 동일한 형식/크기 검사를 사용. 한 영역에 한 파일만 수용하고, 교체 시 이전 결과 무효화. 점검 중/다중/미지원/폴더/영역 밖 드롭은 안내하고 기존 선택 보존
- 서버 전송/추가 CDN/모델 다운로드/브라우저 저장소 사용 없음. 기존 CSP와 worker 네트워크 차단 유지. 원본은 수정하지 않음
- 자산 버전 쿼리로 새 화면과 오래 캐시된 worker의 혼합 방지

## 실제 결과

- `npm test`: **25개 통과**. 기존 12개에 HWP 압축/비압축 표, 본문 및 확장 레코드, 불확실성, 보호 플래그 5종, HWP 97/손상/불연속 섹션, 압축 해제 예산, 병합 표, 미리보기 대체 방지 추가
- `npm run build`: 성공
- `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`: **13개 통과**. 파일 선택과 실제 DataTransfer 드롭 이벤트를 사용
- 준비 완료 후 인터넷 연결을 끊은 상태에서 HWP 3종의 5문항·정답 1~5·각 20점 추출 확인
- HWP/XLSX 드롭 → 근거 보기 → XLSX 4개 시트 다운로드 완료. 이 과정에서 **HTTP 요청 0개** 확인
- 교체 드롭의 역할 유지/기존 결과 무효화, 다중·미지원·영역 밖 드롭의 기존 선택 보존, 점검 중 교체 거절, 보호 HWP 안내 확인
- 기존 DOCX/XLSX/HWPX/PDF, 모바일 가로 넘침 방지, 스캔 PDF/POST 차단 시나리오도 통과

실제 Windows 탐색기에서의 수동 드래그, 한글 편집기 호환 HWP 생성, 모든 학교 양식의 추출 정확도를 검증했다는 뜻은 아닙니다. HWP fixture는 추출 어댑터용 가상 바이너리이며 편집 가능한 완전한 한글 문서를 보장하지 않습니다. 기존 Python 데스크톱 HWP 지원 범위는 바꾸지 않았습니다.

공개 사이트 반영은 검증된 정적 빌드를 `gh-pages`에 push하고 GitHub Pages 작업 성공을 별도로 확인합니다.
