# 1단계 MVP 검증 기록

검증일: 2026-11-02. 모든 입력은 개발용 가상 문항이며 실제 학생/시험 자료를 사용하지 않았습니다.

## 실제 실행 환경

- Debian 13 / Python 3.12.14
- PySide6 6.8.3, openpyxl 3.1.5, python-docx 1.1.2, PyMuPDF 1.25.5, defusedxml 0.7.1
- Qt `QT_QPA_PLATFORM=offscreen`

## 실행 결과

`.venv/bin/python -m pytest -q`: **62 passed, 5 warnings**.

- 명시적인 DOCX/XLSX/HWPX 표의 5문항·정답·배점·총점 추출 확인
- 가상 PDF 본문 5문항 추출 및 불확실성 표시 확인
- 누락/중복/정답·배점 불일치/총점 오류 후보 확인
- 추출 실패, 수식, 병합 표, 숨긴 시트, HWPX 셀 좌표 이상, 잘못된 XLSX dimension, 빈 추출의 보수적 처리 확인
- 스캔/암호화 PDF, 손상 Office 파일, HWPX XML entity, 미지원 확장자 거절 확인
- 원본 해시 보존, 원본·하드링크 덮어쓰기 거절, 보고서 저장 실패 시 기존 파일 보존, 수식 주입 방지 확인
- URL/UNC 경로 거절, 같은 원본을 다른 하드링크로 선택하는 실수 거절 확인
- CLI 정상/오류/확인 필요 종료 코드와 XLSX 생성 확인
- 인터넷 소켓·DNS·UDP 차단 확인
- Qt에서 비동기 점검 → 미리보기 → 오류 필터 → 근거 표시 → 보고서 저장 → 입력 변경 시 결과 무효화 확인
- Qt에서 스캔 PDF 실패 안내와 UI 복구 확인

공식 `main([])` 진입점도 네트워크 차단을 켠 채 실행했습니다. 정상 가상 예제에서 창 표시, 작업 스레드 완료, 5개 문항, 14개 정상 점검 항목, 보고서 저장 버튼 활성화를 확인하고 정상 종료했습니다.

테스트 경고 5개는 PyMuPDF SWIG 타입의 `__module__` 관련 deprecation 경고입니다. 추가 GUI 실행 중 환경의 Fontconfig 캐시 쓰기 경고가 있었으나 한글 렌더링·점검·종료는 정상 동작했습니다.

## 아직 검증하지 않은 범위

- 실제 Windows 10/11 설치/화면/배율/오프라인 wheel 설치: 절차와 CI 정의를 제공했으나 이 Linux 인스턴스에서 실행하지 않음
- Windows 전용 네트워크 드라이브 감지: 코드로 구현했으나 실제 Windows 드라이브에서 실행하지 않음
- 실제 한글 편집기가 만든 다양한 HWPX 양식: 최소 XML fixture만 자동화 테스트; fixture의 편집기 호환성 미보장
- 임의의 학교 양식, PDF 표/다단 복원, OCR, 문항 의미/정답 타당성 검증, 로컬 AI: 1단계 지원/검증 범위 밖
- GitHub Actions 실행, EXE 빌드, 원격 push, 배포/게시: 수행하지 않음

Windows 배포와 실제 사용 전에는 README의 범위에 맞춘 **가상 양식**으로 교사와 함께 검수해야 합니다.
