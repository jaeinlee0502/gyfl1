# 웹 버전 검증 기록

검증일: 2026-11-02. 실제 시험 자료/학생 정보 없이 기존 가상 샘플만 사용했습니다.

## 실제 통과한 검증

- `web/`에서 `npm test`: **12개 통과**. 실제 DOCX/XLSX/HWPX fixture 추출, 정규화, 정상 5문항·14개 점검 항목, 누락/중복/정답·배점/총점 오류 후보, 수식/빈칸의 확인 필요, 문항 0개의 비정상 처리, XML 외부 entity/손상 거절, Decimal 합산, XLSX 수식 주입 방지를 검사했습니다.
- `npm run build`: 성공. PDF 문자맵/표준 폰트가 worker 번들 안에 포함되어 별도 CDN/다운로드 없이 동작합니다.
- `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`: **실제 Chromium 테스트 5개 통과**. 웹 화면 준비 완료 후 네트워크를 끊고 실제 가상 파일을 선택해 검증했습니다.
  - DOCX 원안지/XLSX 정보표의 4개 오류 후보, 원문 근거, 필터, XLSX 다운로드·4개 시트 확인
  - 파일 선택/점검/보고서 다운로드 후 **HTTP 요청 0개** 확인
  - 네트워크 없이 HWPX 및 한글 PDF의 5문항, 정답 1~5, 각 배점 20점 확인
  - 스캔 PDF OCR 미지원 안내 및 이전 결과 무효화 확인
  - 390px 모바일 화면, 가상 예제, 선택/결과 지우기, CSP의 POST/fetch 차단 확인
- 기존 Python 데스크톱 테스트: **62개 통과**, 기존 PyMuPDF SWIG deprecation 경고 5개.

PDF CMap 어댑터의 압축 형식 계약을 수정한 후 위 브라우저 테스트를 모두 다시 실행했습니다. PDF 추출은 성공하더라도 추정 추출이므로 ‘확인 필요’로 표시합니다.

개발 환경은 Linux / Node 24 / 시스템 Chromium이며 실제 Windows Edge/Chrome이나 공개 배포 주소는 아직 검증하지 않았습니다. CI는 Node 22 및 GitHub 호스팅 Chromium을 사용하도록 정의했지만 이번 작업에서 원격 Actions를 실행하지는 않았습니다.

## 라이브러리 점검 범위

설치 중 확인된 xmldom/fflate의 수정 전 버전을 교체하여 각각 0.9.12 / 0.8.3을 고정했습니다. ExcelJS의 npm 의존성에는 Node 전용 archiver/glob/uuid 관련 감사 경고가 남아 있으며 전체 `npm audit` 무경고를 주장하지 않습니다. 정적 브라우저 빌드는 ExcelJS의 브라우저 번들을 사용합니다. 배포 전 및 업데이트 시 의존성·배포물·라이선스를 계속 검토해야 합니다.

## 배포 상태

정적 빌드와 수동 GitHub Pages 배포 workflow, 사용 설명서를 제공했습니다. **원격 push, 공개 사이트 게시, 실제 교사 접속, 운영 URL 검증은 수행하지 않았습니다.** 최초 접속에는 정적 서버 연결이 필요하며 새로고침/새 접속까지 보장하는 오프라인 PWA는 아닙니다.

자세한 배포 절차는 [웹 설명서](../web/README.md)에 있습니다. 실제 학교 양식은 가상 복제본으로 검수해야 하며 문항 내용/정답 타당성/AI 검증은 포함하지 않습니다.
