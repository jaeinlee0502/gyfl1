# 시험출제 통합점검기

대한민국 고등학교 정기시험의 **시험 원안지와 문항정보표를 PC 안에서 대조**하는 한국어 데스크톱 앱입니다. Python 3.12 / PySide6 기반의 1단계 MVP입니다.

파일을 선택하면 문항번호·정답·배점을 읽고, 누락·중복·정답 및 배점 불일치·총점 오류 후보를 표시합니다. 추출 미리보기, 원본 위치/원문 근거, XLSX 점검 보고서를 제공합니다. 원본을 자동 수정하지 않으며 교사가 최종 판단합니다.

**링크 접속용 웹 버전도 추가했습니다.** [`web/` 사용·배포 설명서](web/README.md)를 참고하세요. 교사가 브라우저에서 파일을 선택하면 서버에 업로드하지 않고 PC 안에서 점검합니다. 정적 호스팅 배포를 위한 빌드와 GitHub Pages 수동 배포 설정을 제공하며, 실제 공개 링크는 아직 배포하지 않았습니다. 아래 절차는 기존 Python 데스크톱 버전입니다.

**판정 범위:** 명시적인 문항 메타데이터의 대조입니다. 문항 내용, 역사적 사실관계, 정답의 타당성, 복수 정답 가능성, 발문·선지의 모호성은 아직 검증하지 않습니다. ‘정상’도 문서 전체의 무오류나 출제 승인을 뜻하지 않습니다. AI 기능은 구현하지 않았습니다.

## Windows에서 설치하고 실행하기

대상: **Windows 10/11 64비트, Python 3.12 64비트**. Microsoft Store 별칭 대신 실제 Python 3.12가 설치되어 있는지 `py -3.12 --version`으로 확인하세요. 소스 실행 방식이며 별도 EXE/설치 프로그램은 제공하지 않습니다.

프로젝트 폴더에서 명령 프롬프트 또는 PowerShell을 열어 실행합니다. 활성화 스크립트나 PowerShell 실행 정책 변경은 필요 없습니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_app.py
```

설치가 끝나면 **`실행.bat`을 더블클릭**해도 됩니다. 오류를 확인할 때는 위의 `python.exe run_app.py`를 사용하세요. 설치 시에만 패키지를 내려받으며, 기본 점검·미리보기·보고서 저장에는 인터넷이 필요 없습니다.

### 완전히 오프라인인 PC에 설치

1. 인터넷이 연결된 **같은 Windows 64비트 / Python 3.12 환경**에서 공개 라이브러리만 준비합니다. 실제 시험 자료를 이 PC로 옮길 필요는 없습니다.

   ```powershell
   py -3.12 -m pip download --only-binary=:all: -r requirements.txt -d wheelhouse
   ```

2. 프로젝트, `wheelhouse` 폴더, 필요한 경우 공식 Python 3.12 64비트 오프라인 설치 프로그램을 승인된 저장 매체로 대상 PC에 복사합니다. Linux용 wheel은 Windows에서 사용할 수 없습니다.

3. 대상 PC에서 Python을 설치한 뒤 프로젝트 폴더에서 실행합니다.

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install --no-index --find-links=wheelhouse -r requirements.txt
   .\.venv\Scripts\python.exe run_app.py
   ```

프로그램은 실행 중 패키지·OCR 도구·AI 모델을 다운로드하거나 업데이트하지 않습니다.

## 교사의 기본 사용 순서

1. **시험 원안지**와 **문항정보표**를 각각 선택합니다. 먼저 ‘정상 가상 예제 → 예제 불러오기’로 연습할 수 있습니다.
2. **교사 지정 기준 총점**을 확인합니다. 기본값은 100점이며 다른 총점의 시험이면 변경하세요.
3. **점검 시작**을 누릅니다. 점검은 화면과 분리된 작업 스레드에서 실행합니다.
4. ‘점검 결과’에서 오류/확인 필요 항목을 선택해 원본 위치와 읽은 원문을 확인합니다. ‘원안지 추출’과 ‘정보표 추출’ 탭에서 누락·읽기 순서·문항유형도 확인하세요. 화면은 읽기 전용입니다.
5. **XLSX 보고서 저장**에서 원본과 다른 경로를 선택합니다. 원본 수정은 원래 편집 프로그램에서 교사가 직접 합니다. 입력 파일이나 기준 총점을 바꾸면 기존 결과는 무효화되어 다시 점검해야 합니다.

보고서에는 ‘점검 요약’, ‘점검 결과’, ‘원안지 추출’, ‘정보표 추출’ 시트가 있습니다. 자동 저장/업로드는 없습니다. 보고서는 원본 경로와 원문 일부를 포함하므로 학교의 문서 관리 규정에 따라 보관하세요.

## 입력 형식과 추출 범위

| 입력 | 1단계 지원 범위 | 한계/처리 |
| --- | --- | --- |
| XLSX | 시트의 명시적 문항 표. 모든 시트를 읽음 | 수식은 계산하거나 캐시값을 믿지 않음. 수식/빈칸/병합으로 생긴 빈 값은 확인 필요. 숨긴 시트의 문항도 미리보기에 표시하고 확인 요청 |
| DOCX | 본문에 있는 표 우선. 표가 없으면 아래 한 줄 본문 형식 | 병합된 데이터 행은 확인 필요. 머리말/꼬리말/텍스트 상자/그림/수식 속 문항은 지원 범위 밖 |
| HWPX | `Contents/section*.xml`의 기본 문항 표, 표가 없으면 한 줄 본문 형식 | 로컬 ZIP/XML 파싱. 복잡한 배치, 셀 좌표 이상, 병합·그림·수식 등은 확인 필요. 전체 한글 렌더러가 아님 |
| PDF | 텍스트가 있는 한 줄 본문 형식 | PDF 표의 셀 복원, 다단/복잡한 줄바꿈, 그림 속 문항은 지원하지 않음. 추출 문항은 항상 확인 필요. 텍스트 없는 스캔 PDF는 OCR 미지원 안내 |
| HWP / DOC / XLS / XLSM / 기타 | 미지원 | 원래 편집기에서 HWPX/DOCX/XLSX 또는 텍스트 PDF로 변환 안내. 확장자만 바꾸면 안 됨 |

최대 입력 파일 50MB, 압축 내부 총 크기 100MB / 항목 5,000개, XLSX 시트 20,000행 / 100열, 표 20,000행, PDF 1,000쪽을 지원 한도로 둡니다. 손상/암호화 파일은 거절합니다. 자동 OCR은 없습니다.

### 권장: 명시적인 문항 표

양쪽 문서에 같은 기준의 표를 준비하세요. 실제 시험 원안지에 정답이 없는 경우 정답을 추론하지 않고 ‘확인 필요’로 표시합니다. 인쇄용 원안지에 정답을 넣을 필요는 없으며, 교사용 복사본이나 메타데이터 XLSX를 사용할 수 있습니다.

| 문항번호 | 정답 | 배점 |
| --- | --- | --- |
| 1 | ① | 20 |
| 2 | 2 | 20 |
| 3 | ③ | 20 |
| 4 | 4 | 20 |
| 5 | ⑤ | 20 |
| 합계 | | 100 |

- 헤더는 표/시트의 첫 30행 안에 있어야 합니다. `문항 번호`처럼 공백이 있어도 인식합니다.
- 번호 헤더: `문항번호`, `문제번호`, `문항`, `번호`. 정답: `정답`, `답`, `모범답안`, `예시답안`. 배점: `배점`, `점수`. 번호와 정답/배점 중 하나만 있어도 읽되 부족한 값은 확인을 요청합니다.
- 반복 헤더는 열 위치가 같을 때만 건너뜁니다. 헤더 없는 문항 표, 해석 불가능한 행, 같은 이름의 열이 여러 개인 표는 추출 범위 확인을 요청합니다. 열/표를 임의로 추측해서 합치지 않습니다.
- `유형`/`문항유형`/`구분` 열로 `객관식`과 `서답형`을 구별할 수 있습니다. 또는 번호를 `서답형 1`처럼 적으세요. `서술형`, `단답형`, `논술형`은 같은 서답형 번호 공간으로 취급합니다. 이 유형들 사이에 번호가 다시 시작하면 `1-1` 등 고유 번호를 사용하세요.
- 선택형 `1`과 `객관식 1`은 같은 번호, `서답형 1`은 다른 번호입니다. `1-1` 형식의 소문항도 지원합니다. 번호 0, 식별할 수 없는 유형, 범위 번호 `1~3`은 추정하지 않습니다.
- `①`과 `1`, `①③`과 `1,3`은 같은 정답으로 정규화합니다. 복수 정답에는 원문자 또는 쉼표/슬래시를 사용하세요. `13`은 `1,3`으로 추측하지 않습니다. 서답형은 공백 정리 외에 동의어·수학적 동치 판단을 하지 않습니다.
- 배점은 양수 숫자 또는 `2.5점` 형식입니다. 소수점은 `.`을 사용하세요. `Decimal`로 합산하여 부동소수점 오차를 피합니다. Excel 수식은 값으로 붙여 넣은 별도 복사본을 사용하세요.
- 합계 행 번호 열은 `합계`, `총점`, `총배점`, `배점합계`를 지원합니다. 문항별 배점 합계를 교사 지정 총점 및 원문 표기 총점과 각각 비교합니다. 양쪽 문서 사이의 단순 일치만으로 총점을 통과시키지 않습니다.
- 문항 표와 번호가 있는 본문이 함께 있으면 **표만 대조하고 본문은 별도 확인**을 요청합니다. 표의 일치가 본문 문항의 일치를 검증하지는 않습니다.

### 본문 형식(보조 지원)

한 문항의 번호·정답·배점을 **한 줄/한 문단**에 명시해야 합니다.

```text
1. 가상 색종이의 개수는? [정답: ①] [배점: 20점]
2. 가상 상자의 개수는? [정답: ②] [배점: 20점]
총점: 100점
```

`1. 가상 문항 [20점]`도 문항/배점은 읽되 정답은 확인 필요입니다. 본문에서 발견한 번호는 문항/선지/각주 중 무엇인지 확신할 수 없으므로 **DOCX/HWPX 본문 추출도 항상 확인 필요**입니다. 여러 줄의 문항과 뒤쪽 정답표를 자동으로 연결하거나 그림에서 답을 추론하지 않습니다.

## 판정 규칙

- **오류:** 명시적이고 완전하게 읽힌 표에서 발견한 누락/중복/정답·배점 불일치/총점 불일치 후보. 교사가 실제 오류인지 최종 판단합니다.
- **확인 필요:** PDF/본문 추정 추출, 문항 0개, 해석 실패 행, 읽을 수 없는 정답/배점, 수식·병합·숨긴 시트, 번호 연속성 공백, 중복으로 일대일 대조 불가능, 총점 기준 부재/신뢰할 수 없는 합계 등. 추출이 불완전하면 불일치도 확정 오류로 승격하지 않습니다.
- **정상:** 해당 규칙에서 확실하게 읽은 메타데이터가 일치함. 다른 규칙의 확인 필요나 문항 내용의 오류를 없애지 않습니다.

단일 숫자 문항번호는 두 문서에서 동시에 빠진 번호도 연속성 확인을 요청합니다. `1-1` 형식 소문항의 연속성은 자동 추정하지 않습니다. 시험 문항 수를 따로 입력받지는 않으므로 양쪽에서 **마지막 문항들이 함께 빠진 경우**도 알 수 없습니다. 미리보기의 문항 수를 원본과 대조해야 합니다. 재시작하는 번호와 문항유형을 구분하지 않은 자료는 명시적인 유형/번호로 보완해 주세요.

카운트는 **문항 수가 아닌 점검 항목 수**입니다. 한 문항에 정답과 배점 점검이 각각 생기고, 문서 단위 추출/총점 점검이 추가됩니다.

## 오프라인·원본 보호 설계

- 앱 실행 경로에 외부 API, HTTP 클라이언트, 텔레메트리, 자동 업로드, 모델 다운로드 기능이 없습니다. 사용자가 선택한 로컬 파일만 읽습니다. 문서 내 링크/매크로/스크립트를 실행하지 않습니다.
- URL과 UNC 공유 경로는 입력/보고서 저장 양쪽에서 거절하며 Windows의 네트워크 드라이브도 거절합니다. 프로그램과 자료를 PC의 로컬 디스크로 복사한 뒤 사용하세요.
- 공식 실행 진입점에서 Python audit hook으로 인터넷 소켓 생성, DNS 조회, 연결/전송을 추가 차단합니다. 이 장치는 Python 경로에 대한 방어이며 OS 방화벽이나 임의의 네이티브 플러그인 감시 장치는 아닙니다. Qt 네트워킹/WebEngine을 사용하지 않습니다.
- HWPX는 `defusedxml`로 entity/외부 entity를 거절하고, ZIP 구성 크기를 검사합니다. 파일을 실제 폴더에 압축 해제하지 않습니다. XLSX 외부 링크는 로드하지 않고 수식은 실행하지 않습니다.
- 원본에 대한 쓰기 경로는 없습니다. 보고서 저장은 경로·동일 파일/하드링크를 검사하여 원본 덮어쓰기를 거절합니다. 원문을 보고서 셀에 쓸 때는 수식이 아닌 **문자열**로 저장해 Excel 수식 실행을 방지합니다.
- 점검 결과는 메모리에 두며 파일 선택 이력이나 원문 로그를 저장하지 않습니다. 보고서만 명시적 저장 요청으로 생성됩니다. 보고서 임시 파일은 선택한 폴더에서 저장 완료 후 교체·정리합니다. 저장 도중 강제 종료 시 남은 `.exam-report-*.xlsx`는 보고서와 동일하게 관리/삭제하세요.

개발과 테스트에는 `samples/` 및 테스트 중 생성하는 가상 자료만 사용합니다. 운영 자료는 Git 저장소나 이슈에 올리지 마세요.

## 가상 예제와 테스트

[샘플 설명](samples/README.md)에 정상/오류/불확실/PDF/스캔 사례를 정리했습니다. 정상 사례는 `exam.docx` ↔ `info_ok.xlsx`, 오류 사례는 `exam.docx` ↔ `info_errors.xlsx`입니다. HWPX 샘플은 **XML 어댑터용 최소 fixture**이며 한글 편집기용 완전한 문서는 아닙니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

테스트는 정상/누락/중복/정답·배점/총점/소수점/불확실 추출, DOCX/XLSX/HWPX/PDF, 스캔·암호화·손상 입력, 원본 해시 보존, 수식 주입 방지, 네트워크 차단, CLI와 Qt 화면에서의 점검→미리보기→보고서 저장을 검사합니다. Qt 테스트는 화면 없는 `offscreen` 모드이며 실제 Windows 설치/화면 검증과는 구별해야 합니다.

Linux 개발 환경에서는 다음과 같이 실행합니다.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/python run_app.py  # 데스크톱/디스플레이 필요
```

가상 샘플 재생성(기존 샘플을 덮어씀):

```powershell
.\.venv\Scripts\python.exe scripts\generate_samples.py --force
```

### 화면 없는 실행

```powershell
.\.venv\Scripts\python.exe -m exam_checker check --exam samples\exam.docx --info samples\info_ok.xlsx --expected-total 100 --report 점검보고서.xlsx
```

종료 코드: `0` = 모두 정상, `1` = 오류 후보 있음, `2` = 오류 없이 확인 필요 있음, `3` = 입력/저장 실패. `--report`를 생략하면 파일을 만들지 않습니다. CLI도 동일한 네트워크 차단과 대조 엔진을 사용합니다.

## 프로젝트 구조와 2단계 경계

```text
exam_checker/
  __main__.py        GUI/CLI 진입점
  offline.py         Python 네트워크 차단
  paths.py           로컬 경로/Windows 드라이브 검사
  models.py          원문 근거·추출 결과·점검 판정 모델
  normalize.py       번호·정답·Decimal 배점 정규화
  extractors/        XLSX / DOCX / HWPX / PDF 로컬 어댑터
  checker.py         결정적 문서 대조·총점 규칙
  service.py         파일 → 추출 → 대조 파이프라인
  report.py          원본을 보호하는 XLSX 보고서
  ui.py              한국어 PySide6 화면/작업 스레드
  review/contracts.py  향후 로컬 AI ‘검토 의견’ 계약만 정의
scripts/generate_samples.py
samples/             가상 자료
tests/               자동화 테스트
run_app.py / 실행.bat
requirements.txt / requirements-dev.txt
```

2단계는 별도의 로컬 모델 어댑터가 `ReviewOpinion`을 반환하도록 경계만 정의했습니다. 의견·원문 근거·불확실성·‘검토 의견’ 라벨을 보유하며 1단계 오류/정상 판정과 자동 합치지 않습니다. 모델/추론 엔진/외부 AI API 연결/다운로드 UI는 추가하지 않았습니다. 실제 추가 시 사용자가 별도로 준비한 로컬 모델과 명시적 실행 흐름을 설계해야 합니다.

## 라이브러리 선택과 배포 전 확인

| 라이브러리 | 사용 목적 |
| --- | --- |
| PySide6 | 네이티브 Qt 데스크톱 UI, 파일 선택, 작업 스레드 |
| openpyxl | XLSX 읽기 및 보고서 쓰기. Excel 설치 불필요 |
| python-docx | DOCX의 기본 표/문단 읽기. Word 설치 불필요 |
| PyMuPDF | 로컬 PDF 텍스트 추출. OCR은 사용하지 않음 |
| defusedxml + 표준 zipfile | HWPX XML의 제한적 읽기. 한글 COM 자동화/한글 설치에 의존하지 않음 |

주요 직접 의존성은 `requirements.txt`에 버전을 고정했습니다. Windows 배포 시에는 PySide6/Qt의 LGPL/GPL/상용 라이선스 및 **PyMuPDF의 AGPL/상용 라이선스**를 포함한 각 의존성의 배포 조건을 검토해야 합니다.

현재 클라우드 검증 대상은 Python 3.12/Linux와 Qt offscreen입니다. Windows 배포 전에는 Windows 10/11 실제 화면, 고해상도 배율/한글 경로, 학교에서 사용하는 HWPX·DOCX 표 양식의 **가상 복제본**으로 검수하세요. 임의의 학교 양식 전체에 대한 추출 정확도나 실제 한글 편집기 호환성을 보장하지 않습니다.

이번 실행의 검증 근거는 [검증 기록](docs/validation.md)에 정리했습니다.

`.github/workflows/tests.yml`에는 Python 3.12의 Windows/Linux 테스트 작업을 정의했습니다. 이 파일의 제공은 GitHub Actions 실행/통과를 뜻하지 않으며, 원격 push나 배포는 이 작업에서 수행하지 않습니다.
