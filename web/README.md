# 링크로 접속하는 웹 버전

Python/PySide6 앱과 별도로 동작하는 **서버 업로드 없는 정적 웹 앱**입니다. 최신 데스크톱 Edge/Chrome에서 링크를 열고 두 파일을 선택하면 브라우저가 읽고 점검합니다. 교사 PC에 Python을 설치할 필요가 없습니다.

## 파일의 이동 경로

```text
배포 서버 ── 화면·프로그램 파일 ──▶ 선생님의 브라우저
                                       │
선생님 PC의 원안지·문항정보표 ── 로컬 읽기
                                       │
                              브라우저 작업 스레드에서 추출·대조
                                       │
                              화면 미리보기 / PC로 XLSX 저장
```

**문서를 서버로 보내는 경로는 없습니다.** 업로드 API·백엔드·DB·외부 AI API·계정·분석 도구·광고·CDN·자동 업데이트를 사용하지 않습니다. 파일명/원문/결과를 HTTP 요청이나 브라우저 저장소에 넣지 않습니다. DOM에는 `textContent`로만 표시하고 Excel 결과는 수식이 아닌 문자열로 저장합니다.

페이지의 CSP는 `connect-src 'none'`, `form-action 'none'`이며 파싱 작업 스레드도 fetch/XHR/WebSocket 등을 거절합니다. PDF.js의 문자맵/표준 폰트까지 빌드에 포함하여 문서를 처리하는 중 추가 다운로드가 필요하지 않습니다. XML 외부 entity/DOCTYPE를 거절합니다.

처음 페이지를 여는 데는 인터넷이 필요하며 배포 서버에는 일반 접속 기록(IP 등)이 남을 수 있습니다. ‘준비 완료’ 후 연결을 끊고도 파일 선택·점검·보고서 다운로드가 가능합니다. **새로고침/새 접속까지 오프라인 지원하는 PWA는 아닙니다.** 교사 PC의 브라우저 확장 기능, OS/클라우드 동기화와 호스팅 업체의 임의 스크립트 삽입까지 통제하는 도구는 아닙니다. 학교가 허용한 환경에서 사용하세요.

## 기능과 범위

- 파일 선택 2개, 교사 지정 기준 총점, 가상 오류 예제, 점검 상태 필터, 원본 근거 펼쳐보기, 양쪽 추출 미리보기, XLSX 다운로드, 선택/결과 지우기
- XLSX/DOCX/HWPX의 명시적인 `문항번호 / 정답 / 배점` 표 우선 지원. 총점/누락/중복/정답·배점 대조 규칙은 데스크톱 버전과 같은 원칙
- 본문/PDF 한 줄 문항은 추정 추출하여 항상 확인 필요. 예: `1. 가상 문항 [정답: ①] [배점: 20점]`
- 수식/병합/해석 불가 행/숨긴 시트/불명확한 추출은 확인 필요. 빈 문항을 정상으로 처리하지 않음
- 파일별 50MB, 압축 해제 100MB/5,000항목, 시트/표 20,000행, XLSX 100열, PDF 1,000쪽. 작업 시간 45초 한도 후 작업 스레드 종료. 스캔 PDF/OCR, 암호화 문서, 구형 HWP, 문항 의미/AI 점검 미지원
- 문항번호의 앞/중간 공백은 확인 요청하나 양쪽에서 동시에 빠진 마지막 문항은 알 수 없음. 실제 문항 수를 교사가 확인해야 함
- 같은 내용의 파일을 양쪽에 선택하면 실수 가능성이 있어 거절. 보고서 파일명은 원본과 다른 기본 이름 제공. 브라우저 다운로드에서 사용자가 직접 기존 파일을 덮어쓰는지 여부/네트워크 드라이브 선택은 브라우저/OS가 관리함
- ‘지우기’는 앱의 파일/결과 참조를 비우고 작업 스레드를 재시작함. 물리적인 메모리 완전 삭제 보장은 아님

전체 양식/판정 설명은 상위 [README](../README.md)를 참고하세요. 웹 버전은 Python 코드를 서버에서 실행하지 않고 로컬 JavaScript 어댑터와 `decimal.js` 대조 엔진을 사용합니다. 추출기 차이에 따른 결과 차이가 있을 수 있으므로 양쪽을 자동 동기화된 제품으로 보장하지 않습니다.

## 개발·빌드

Node.js 22 이상을 사용합니다. `web/` 폴더에서:

```bash
npm ci
npm test
npm run build
npm start
```

`npm ci`만 공개 패키지를 다운로드합니다. 빌드는 이후 로컬 의존성과 샘플만 사용합니다. `dist/`에 HTML/CSS/JS와 라이브러리 고지 파일이 생성되며 서버 측 Python/Node 런타임 없이 정적 호스팅으로 배포할 수 있습니다. `file://` 더블클릭 실행은 모듈/작업 스레드 정책 때문에 지원하지 않습니다.

개발 서버는 루프백에만 바인딩하고 GET/HEAD 정적 파일만 제공합니다. 문서 수신이나 업로드 저장 기능은 없습니다. 공개 운영에 이 개발 서버를 쓰지 말고 아래 정적 호스팅을 사용하세요.

## 선생님들에게 줄 링크 만들기

권장 배포 예시는 **GitHub Pages**입니다. 문서는 GitHub에 올리지 않고, 프로그램 소스와 정적 빌드 파일만 게시합니다.

1. 이 프로젝트의 소스를 대상 GitHub 저장소에 커밋/push합니다. 실제 시험 자료와 보고서, `.venv`, `node_modules`는 올리지 마세요.
2. 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions**로 설정합니다. Pages 사용 가능 여부는 저장소 공개 범위와 요금제에 따라 다릅니다.
3. **Actions → 웹 점검기 수동 배포 → Run workflow**를 실행합니다. 자동 배포가 아닌 수동 실행으로 정의되어 있습니다.
4. 작업이 성공하면 `deploy` 작업에 표시되는 **실제 배포 URL**을 교사에게 전달합니다. 배포 전에는 공개 주소가 생기지 않습니다.
5. 운영 주소를 열고 가상 예제로 점검/보고서 다운로드를 확인한 뒤 네트워크를 끊어서 다시 테스트하세요.

학교의 승인된 HTTPS 정적 웹 서버에 `web/dist/`의 내용을 그대로 올려도 됩니다. 하위 경로 배포를 지원합니다. 호스팅 업체의 분석/광고/자동 스크립트 삽입은 끄세요. 게시 권한과 배포 소스 변경 권한은 담당자에게만 부여하세요. 검증한 빌드를 보존하고 의존성/라이선스도 점검하세요.

**이 작업에서는 원격 push나 실제 공개 배포를 하지 않습니다.** 설정과 빌드 산출물을 제공하는 것과 실제 링크가 활성화된 것은 별개입니다.

## 테스트

```bash
npm test
npm run build
npm exec playwright install chromium
npm run test:e2e
```

이미 설치된 Chromium을 사용할 경우 `CHROMIUM_PATH`에 실행 파일 경로를 지정할 수 있습니다. E2E는 실제 브라우저로 파일 선택→점검→근거/미리보기→XLSX 다운로드를 수행하며, 준비 완료 후 네트워크를 끊은 상태에서도 점검하고 HTTP 요청이 발생하지 않는지 검사합니다. 테스트에는 상위 `samples/`의 가상 자료만 사용합니다. PDF/브라우저 결과의 실제 학교 양식 검수는 별도로 필요합니다.

실제 실행 결과: 단위 테스트 12개, Chromium E2E 5개, 기존 Python 테스트 62개 통과. [웹 검증 기록](../docs/web-validation.md)을 참고하세요. 실제 공개 사이트/Windows 브라우저 검수와는 구별됩니다.
